# 実行手順書 — 実データ化の受け入れ（hiroki 本人が行う作業）

対象: 設計.md（D-01〜D-14）を実装した版。コードと単体・結合テストは AI スタッフが済ませています。この手順書は、**本物の Supabase と本物の鍵が要る作業**だけを、hiroki 本人が行うためのものです。

## 守ること

- 鍵（`SUPABASE_SERVICE_KEY`）、パスワード（`APP_PASSWORD`）、URL の値は、次の 2 か所にだけ入れます。
  1. 自分の PC の `.streamlit/secrets.toml`（`.gitignore` 済み）
  2. Streamlit Community Cloud の Secrets 画面
- チャット、AI、GitHub、スクリーンショット、Issue には貼りません。誤って貼ったら、Supabase 側で鍵を再発行し、secrets を差し替えます。
- 実際の体重は、手順 5 以降で自分の画面から入れます。テストに実データは使いません。

## 受領項目リスト（hiroki が用意する値）

| 名前 | 何か | 取得場所 | 入れる場所 |
| --- | --- | --- | --- |
| `SUPABASE_URL` | Project URL | Supabase 管理画面 → 対象プロジェクト → Project Settings → API | ローカル secrets.toml、Cloud の Secrets |
| `SUPABASE_SERVICE_KEY` | サーバ専用の秘密鍵（従来の呼び名は service_role。新しい画面では secret key などの名前の場合がある） | 同じ画面の API Keys。**必ず「サーバ専用・RLS を迂回する鍵」を選ぶ**。公開用（anon / publishable）ではない | 同上 |
| `APP_PASSWORD` | 画面ゲート用のパスワード | Supabase からは取れない。自分で決める（16 文字以上のランダム文字列、パスワードマネージャで作成） | 同上 |
| （任意）`SUPABASE_PUBLIC_KEY` | 公開用の anon / publishable キー | 同じ API Keys 画面 | 手順 4 の確認コマンドの環境変数にだけ使う。ファイルには書かない |

## 手順

### 0. 起動に使う Python に依存パッケージを入れる（約 3 分）

`streamlit run` を動かす Python に `supabase` が入っていないと、ログインのあとに「データベースに接続できませんでした」と出ます（原因は鍵ではありません）。次で確かめ、入っていなければ入れます。

```bash
python -c "from supabase import create_client; print('ok')"   # ok と出れば入っている
pip install -r requirements.txt                                  # 出なければ入れる
```

- `python` と `pip` と `streamlit` は**同じ環境**のものを使ってください（`which python pip streamlit` の場所がそろっているか確認）。conda と別の Python が混ざっていると、ここで食い違います。
- 入っていないときは、原因がターミナルにも出ます（`supabase パッケージを読み込めません…`）。

### 1. Supabase の準備（約 10 分）

1. Supabase にログインし、使うプロジェクトを開きます。プロジェクトが「一時停止」になっていたら再開します（無料プランは、しばらく使わないと停止する仕様があります。条件は Supabase の最新の案内で確認してください）。
2. SQL Editor を開き、`migrations/0001_create_diet_data.sql` の中身を貼って実行します。エラーが出なければ完了です。
3. Table Editor で `diet_data` を開き、**RLS が有効**と表示されていることを確認します。
   - この DDL は、AI スタッフの手元に Postgres が無く、実行して確かめられていません。エラーが出たら、エラー文（鍵を含まない部分）をそのまま god に伝えてください。

### 2. secrets の設定（約 5 分）

1. `.streamlit/secrets.toml.example` をコピーして `.streamlit/secrets.toml` を作ります。
2. 上の受領項目リストの 3 つの値を入れます。
3. `git status` に `.streamlit/secrets.toml` が**出てこない**ことを確認します。

### 3. ローカルで起動して動きを見る（約 10 分）

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

確認すること:
- 最初はパスワード入力だけが出る。間違えるとエラーになり、5 回続けると 60 秒ロックされる
- 正しいパスワードで入ると、「まず①で目標プランを保存してください」と出る（DB が空のため）
- ①で目標を保存 → 今週の目安と週次プランが出る。Supabase の Table Editor に `setting` の行が 4 つできる
- ③で体重を記録 → `log` の行が 1 つできる。同じ日を続けて記録しても 1 行のまま
- ブラウザを再読み込みするとパスワードを求められる（仕様どおり）
- サイドバーの「データをリセット」は、チェックを入れないと消えない。**実データを入れる前に試してください**（入れたあとに試すと消えます）

### 4. 本物の DB での自動確認（I-11 / I-12 / I-13、約 5 分）

```bash
python scripts/live_smoke.py
# 公開用キーの確認も行う場合（キーは履歴に残らないよう、この 1 コマンドの中だけで渡す）
SUPABASE_PUBLIC_KEY='<公開用キー>' python scripts/live_smoke.py
```

- 触るのはマーカー行（`log`、`1999-01-01`）だけで、終わると削除します。全消去は行いません。
- 鍵は画面に出ません。`[FAIL]` が出たら、その行をそのまま god に伝えてください。
- 期待する結果: I-11 が 3 件、I-12 が 5 件（DB の制約 23514 で拒否）、I-13 が 2 件（権限エラー 42501）すべて `[PASS]`。

### 5. Community Cloud（I-14、約 15 分）

1. アプリの Settings → Secrets に、`.streamlit/secrets.toml.example` の 3 行を、自分の値で貼ります。
2. `requirements.txt` を含む変更を push して、デプロイします（Python 3.11）。
3. デプロイ後の URL を開き、次を確認します。
   - パスワード無しでは何も見えない
   - ログイン → 体重を 1 件記録
   - アプリを Reboot（Manage app → Reboot）→ 再度ログイン → **記録が残っている**
4. 日本時間の 0〜9 時に開き、「記録する日付」の初期値が**今日（日本の日付）**になっていることを確認します（サーバが UTC でも日本時間で動く設計です）。

### 6. 完了したら

上の結果（PASS / FAIL の行）を god に返してください。値や鍵は含めないでください。

## うまくいかないとき

| 症状 | 見立て |
| --- | --- |
| 画面に「データベースに接続できませんでした」 | まず手順 0（`supabase` が入っているか）を確認する。次に、プロジェクトが一時停止している、URL または鍵の値が違う、ネットワーク。停止なら再開する。ターミナルのログに原因の種類が出る |
| 画面に「設定が不足しています: …」 | secrets に名前が無い、または空。名前だけが表示され、値は表示されません |
| 画面に「パスワードが設定されていない…」 | `APP_PASSWORD` が未設定 |
| SQL 実行でエラー | エラー文を god に伝える（DDL は未実行のまま提出しているため） |
| 鍵を貼ってしまった | Supabase で鍵を再発行し、secrets を差し替える |
